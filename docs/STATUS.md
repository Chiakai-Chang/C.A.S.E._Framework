## 證據能支持什麼

M0 收斂提交 `1611f93` 通過 310 個核心測試、63 個評估測試與 140 個 conformance 案例；34 份結果通過外部完整性驗證。這證明受控條件下的行為，沒有證明日常可用性。

選定的 r6 基線 B0（Markdown＋Git）四案皆偵測成功；配對 M0 四案都在 Windows 初始化時無效，尚未測到目標行為。因此無法宣稱 M0 較好、降低 token 或減少人的負擔。完整限定見 [基準報告](evaluation/m0-baseline-report.md)。

## 接下來依序通過的門檻

1. **一個真實平台能跑通。** 先評估一個本機檔案系統 adapter 的成本與必要保證，完成其路徑、鎖、程序身分與原子寫入能力；通過既有 corpus，並由公開 CLI 完成初始化至驗收及失效檢查。若成本過高，重新縮小保證與功能，留下規格變更理由。
2. **證明值得使用。** 凍結新的方法提交，以新 r7+ 身分重新預註冊並執行四組 B0/M0 比較；觀察正確性、人的抉擇與恢復次數、context/token、等待與維護成本。無效結果保留且不得算成功。
3. **降低使用門檻。** 證據支持後才設計漸進載入的 skill 與宿主薄整合，先完成一個宿主旅程，再驗證第二個宿主交接；共用協定不等於已完成跨宿主相容性。
4. **準備公開版本。** 選定授權、完善安裝／升級／移除與資料保留說明、明列支援矩陣，再決定發布形式與版本。

目前不排承諾日期。每個門檻都以「是否用更少認知與抉擇成本換得可驗證品質」復盤，未通過就縮小或停止該方向。
