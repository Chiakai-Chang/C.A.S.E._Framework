耗時 **343.108 秒**，**220,286 SDK 累計 tokens**，人工介入 0、無壓縮、來源未變、無額外產物，診斷未丟棄事件。另有兩次不在允許清單的畸形路徑請求，工具均回報找不到檔案，沒有讀到未授權內容；既有評估器仍如實記錄 `toolPaths: violated`，未為通過改評分規則。

## 已定位的問題

### 1. 取得與引用正確，推論仍錯

worker 與 reviewer 都完整讀過 ARCHITECTURE.md；integrator 也完整讀過，後來另讀 1–40 及 26–35 行。凍結來源第 21 行說明 pi SDK 負責新 session 及依序執行，第 35 行區分 pi 與尚無整合的 Codex／Claude／Antigravity。

reviewer 的理由卻把「三個其他工具尚無整合」當成空陣列的依據；integrator 也接受空陣列。可確認為錯誤推論與漏驗，不是唯一正確來源不存在。獨立 session 能隔開 history，不能保證模型不犯同一種錯誤；本次沒有壓縮，不能歸咎壓縮漏料。

7 個接受的引用都對得上當次真正的讀取回條、來源 SHA256 與返回行段，判斷文字也未被程式改寫。因此上次引用功能的窄保證成立，但**來源識別正確沒有改善這個語意缺陷**。reviewer 的接受引用亦未包含 ARCHITECTURE.md，雖然它確實讀過；不能假裝已建立逐項主張與支持段落的關係。

### 2. 引用修復增加成本，但沒有隱藏

integrator 四次提交不存在的 ID，均遭 `INVALID_CITATION` 拒收，之後使用真實 ID 才被接受。這是預定的同 session 修復，不是新增 session 或額度。`replyCorrections: 0` 僅指最後文字補問為零，不能說沒有修正：工具結果裡仍有四次拒收。

### 3. 前題完整雜湊出現在本次捏造引用：來源尚待查明

無效 ID 中的 `5ab9f8e8a12bcf8a53126e0350dd064d48ba44f87b316780e92d07af87a6ee90` 精確等於上一主題 HOSTS.md 的 SHA256；它不在本次 holdout 任務、三份來源或任何角色交辦文字內。integrator 首次 payload 記錄僅有 system 與 user，四個 session ID 不同，trace 的額外政策清單為空。

這是具體異常，**不是已證實的服務快取污染**。目前保存的是非工具文字的雜湊／字數，不是所有 HTTP 原文，尚不能排除未捕捉的輸入或服務／SDK 狀態。既有[快取研究](../research/2026-09-06-recurrent-cache-triage.md)沒有證明本次根因；舊 build 的推論也不能直接外推到目前服務。不得因此清理 AppData、重建 pi、重啟服務或改 MTP。

### 4. 路徑違規是畸形參數，不是已知資料外洩

reviewer 把五個檔名的 JSON 清單塞進單一 path，之後把 `["."]` 塞進列目錄 path；兩次都 ENOENT。後續成功逐檔讀取。保留評估器的違規分類，同時明確區分錯誤請求與成功越界存取，不誇大也不抹除。
