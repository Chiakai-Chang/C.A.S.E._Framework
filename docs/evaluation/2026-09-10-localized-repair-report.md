[固定 manifest](2026-09-10-planning-feedback-manifest.json)、[完整證據](2026-09-10-planning-feedback-evidence.json)。本次先改善計畫引用錯誤回饋，指出工作包、檢查及合法 ID；交辦說明明示 delivery 位於 inputs 項目。原拒絕條件、目標、資料、模型、off、32K context、4096 輸出、16 回合／session、600 秒總預算不變。

正常流程為 planner → worker → reviewer → worker → reviewer，601.698 秒以 CANCELLED 結束，未進入 integrator，最終成果也不合格。SDK 累計 489,391 tokens（含快取，非峰值 context，未回報成本未知）。來源、requirements、最終範圍及記錄中的工具／政策檢查通過；受測程式未改，人工介入 0。

規劃至執行 45.640 秒，執行至第一次核對 129.721 秒（含交接等成本）。規劃者沒有先推得全部答案，也沒有錯誤 ID 拒收；因此沒有觀察到新錯誤訊息實際協助修正。它明確選擇五份材料全部 inline，不能說此次進展證明索引較好。這是單次、不同版本的觀察，不是因果或效能基準。

真正的新發現是返修回歸：

1. 第一次產物將 `allowsUpdateAndUninstallTogether` 寫成 true；獨立核對正確指出來源程式禁止兩者並用。
2. 原產物的 `installerRelated` 包含正確的「封裝設定」。
3. 返修者改成 false，卻以完整檔案重寫漏掉「封裝設定」。第一次產物 SHA256 為 `60f81c3859f039c848585df4c8b11374661f7f256980feee2501f0da0654ed93`，返修後為 `d38bedf680ecda13dc3d5b5282f8ab266397fe9bc484cb589b4b894e7235aed9`；讀取正文與寫入回條均保存。
4. 第二次核對未完成便取消；不把第一次正確發現、返修者的完成聲明或正確布林值抵銷新缺漏。

可定位的工具缺口：原先只有完整寫檔能力，局部修正仍須重新生成其餘內容。這不證明所有錯誤都源於工具，但給出可直接驗證、比繼續追加提醒更具體的改善。

## 修正：受限的 case_edit

僅提供給 worker，沿用 writeScope、受保護路徑及既有檔案限制；要求目前來源 SHA256、唯一且完全匹配的 oldText 與 newText。版本過期、匹配不存在或多次出現都拒絕而不改檔；保留範圍外的 UTF-8 內容、BOM 與換行，至多 1 MiB。SDK 保存寫入範圍觀察，trace 僅保存前後版本及大小，不保存替換正文。不是語意保證、作業系統沙箱或跨程序原子交易。

測試先確認缺少工具／trace 接線及 evaluator 尚不認得合法修改，再實作至通過。獨立審閱發現 oldText 可含孤立 surrogate，可能命中 emoji 的半個字元；另以 `a😀b` 真實檔案反例重現，補上 oldText／newText UTF-8 round-trip 拒絕，驗證拒絕後檔案不變。審閱者再次確認修正，未新增發現。
