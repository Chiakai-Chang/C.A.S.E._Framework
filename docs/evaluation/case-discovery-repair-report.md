# 即時發現、自查修復與接續：驗收及復盤

日期：2026-09-06。目標仍是讓本地模型在有限 context 下把工作做好、減少人的補述與監督。本次補完已批准的生命週期，不新增角色平台、不要求 GitHub Issue／PR，也不以文件或測試數代替模型成果。

## 已核對的結果

程式回歸 **169/169 通過**。獨立審閱先重現兩項重要問題，修正後相關 36 案複核通過；技能的四個實際操作情境與新增分頁情境已核對。技能驗證需在 Windows Python 使用 UTF-8 模式；首次因系統 cp950 讀取失敗，改以 `python -X utf8` 後通過，未修改全域設定。

收尾再次執行全部 169 案，零失敗、零略過；23 份相關文件的 209 個本地路徑連結均存在（未宣稱逐一驗證頁內錨點）。七份公開探測摘要與原始紀錄的 SHA256、通過與否、耗時及 session 數一致；技能結構驗證及差異空白檢查通過。

真實模型使用目前本機 Qwen3.8-27B Orcarouter／llama.cpp 服務、pi 0.84.2 SDK；探測使用獨立專案與設定目錄、thinking medium、宣告 context 32768、maxTokens 4096、每 session 12 回合。不修改現用模型服務或全域 pi。這是工程探測，不是未見任務或固定版效益比較。

封裝 dry-run 通過：33 檔，包含 discovery 核心及 pi 接線，沒有 evaluation、認證或私有快取。全域 npm 12.0.2 的 dry-run 曾退出 1 且沒有有效原因；改用 Node 隨附 npm 後成功，未修改全域安裝。技能建立／驗證方法促使指引以短入口加按需參照呈現，並以具體操作情境修補歧義，而非把整份設計塞入技能入口。

第四次另開十五分鐘的新探測，因第三次觀察到的恢復路徑需九個 session；未重置第三次卷宗預算，也未改驗收標準。第四次在 415.643 秒內通過。self-repair 02 的並行拒收不冒充缺檔拒收；後續只釐清測試指令為「第一個回覆只呼叫一次提交並等待」，產品程式及評分條件不變。[公開證據摘要](case-discovery-repair-evidence.json)保留版本雜湊、各次設定／成本／失敗與原始檔位置。完整原始紀錄在忽略的 `.npm-cache/*probe-20260906-*.json`，沒有用新成功覆寫舊結果。

## 問題、處理與可重用經驗

1. **需求追蹤不完整。** 先前只補缺檔提交，漏了即時發現到處置、補包、接續的關係。現在用[同一份需求對照](../design/2026-09-06-discovery-and-repair.md#需求到交付的單一追蹤)連到實作、測試、技能與來源；不是另加一套人工填表。
2. **過期等待狀態。** 成功重規劃未清 waitingReason，會讓兩包 verified 仍無法整合。現在成功補做計畫清除已被解決的等待資訊，其他真實未決待辦仍阻擋；有回歸反例。
3. **待辦本身塞滿 context。** 8 筆合法長發現便可超過 48k。改成短索引＋與角色／卷宗綁定的唯讀分頁，完整證據留在權威狀態；不能只限制檔案材料，卻讓協調歷史無限制累積進提示。
4. **回報成功後仍等待模型自行結束。** discovery 01 真實暴露此問題。現在 accepted 後由程式停止生成、交回外層，相同結果重送回原收據；拒絕後的修復、取消與後續工具限制仍保留。這是控制流程修正，不是放寬成果驗收。
5. **新舊回報指引重疊。** discovery 02 選到舊路線；已精簡新 worker 指引，但不能由一次試驗推論提示是唯一原因，也不能強迫更改評分標準掩蓋未進佇列。
6. **未知欄位可能被靜默忽略。** worker 回報現在只接受互斥的 summary／blocked／changeRequest 結構，額外或混合欄位會提供明確錯誤。舊結構化回饋仍保存在 attempt／run；自由文字 summary 不會被自動解析成待辦，不能宣稱模型提過的每件事都已入列。
7. **測試自身也要驗收。** self-repair 02 的成果完成不代表測到指定反例；保留未通過結果，僅消除注入指令對並行工具的歧義，不放寬判準。SDK 所報 tokens 包含快取讀取，設定中的零 API 價格不等於機器成本為零；峰值 context 與本機能源成本未測量。

## 驗收方法與限制

- discovery 案由操作者刻意提供缺前置的計畫，以四份合成訂單／價格／退貨／匯率資料產出 normalized 與 report。成功須同時有 blocking discovery 已採納、完整 completed、兩份精確 JSON、來源未改及執行期間程式雜湊不變；不是只檢查工具有沒有登錄。
- self-repair 是明示故障注入，不代表模型自然會先犯該錯或主動發現所有錯誤。成功須有同一 worker 的 `Missing result.json` 拒收 → 真實寫入 → 再提交，以及獨立核對／整合、精確產物及來源保留。
- 模型可能漏報、錯用工具或違反文字約束。已核准的確定性檢查、來源版本及獨立核對仍必要；自我驗收不是零失敗保證。對已授權修復採有限預算，不自行提高預算或模型權限。
- 以上不能證明普遍提高品質、省 tokens、長 context 效益或其他模型／AI 工具已實測。先前[六筆價值比較](case-value-validation-report.md)照實保留；新程序修復不能改寫舊樣本。
- Codex／Claude Code／Antigravity 仍是可攜技能與核心；pi 是本次自動整合。沒有新增跨產品原生 runner、OS sandbox、多機交易或排程。
