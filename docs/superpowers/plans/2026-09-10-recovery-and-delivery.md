# 中斷後收斂與交付計畫

> 執行者：使用 `superpowers:executing-plans` 逐項接續；本計畫不要求新增分工或重跑已完成研究。

**目標：** 讓本地模型在有限 context 下完成正確成果、合理修復與接續，減少使用者救援；本輪收斂既有異議功能、補足有鑑別力的驗證並整理交付。

**架構：** 保留共用核心、可攜技能與 pi 薄整合層。模型提出判斷，程式保障來源版本、權限、狀態及預算；不因 Codex 自動審查中斷改造 CASE 的產品架構。

**技術：** 既有 Node.js／ES modules、Node test runner、pi SDK 與使用者現用本機模型。

**依據：** [目標](../../GOALS.md)、[已同意的異議設計與中斷復盤](../../design/2026-09-10-review-dispute-boundary.md)、[原始構想對照](../../research/2026-09-05-layered-cooperation-direction.md)。本計畫是接續順序，不取代原需求追蹤。

## 全域限制與這次教訓

- 已成功的測試不為了補紀錄而重跑；原始資料先保存，報告可稍後整理。
- 保存證據、文件、封裝與停止模型各自執行；需權限的清理不作其他收尾的前置。
- 自動審查錯誤、模型行為、產品錯誤、npm 環境問題分開記錄。未知原因不推成全域環境損毀。
- 被拒絕的操作不改用其他路徑繞過；不重建 pi／npm、不清理 AppData、不兌換額度、不改模型或帳號設定。
- 模型服務先核對現況及來源；不重複啟動、不停止無法確認歸屬的程序。若需新權限，只暫停該操作並明確請求，不擋獨立工作。
- 沿用原總預算與權限，不以重試重置成本。不同批次、合成狀態與真實整案結果不得拼成一次端到端成功。
- 主要文件用臺灣正體中文；維護關聯遵循 `docs/MAINTENANCE.md`。本輪不加角色、排程、資料庫或通用 runtime。
