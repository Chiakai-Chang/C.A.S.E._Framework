## 按責任邊界檢查覆蓋

下表避免只看成功路徑，不宣稱窮盡所有任務。跨欄問題依主要責任處理，不複製同義待辦。

| 面向 | 必須考慮 | 現況與下一步 |
|---|---|---|
| 目標與完成條件 | 漏需求、矛盾／歧義、目標變更 | 已有契約與驗收對應；不可把測題答案變成通用要求，重大目標變更仍由使用者決定 |
| 材料與 context | 缺料、過期、索引未讀、交接遺漏 | 已有版本與按需材料；來源有效不等於理解正確，接續仍需保留未解問題 |
| 執行與副作用 | 局部錯誤、部分寫入、工具中斷、舊程序仍在跑 | 已有自查及限定寫入；未知副作用不能盲目重播 |
| 驗收與返修 | 真失敗、誤放行、錯誤否決、修復回歸 | 已有檢查、返修及異議；接上適用的實際檢查，無機械檢查時仍須語意核對，不宣稱通用正確性保證 |
| 規劃與新增工作 | 缺前置、跨包修改、去重、獨立工作可繼續 | 已有 discovery／amendment；用完整旅程驗接線。固定重規劃上限是否提前停止仍需具體判斷 |
| 接續與資源 | session 結束、重啟、取消、期限、總預算、無進展 | 本批修正已過期仍開模型；尚未統一所有自動恢復分類，不能宣稱無人介入接續完成 |
| 結案與重開 | 包通過但整體有缺口、結案後發現錯誤、外部修改 | 全域驗收已存在；completed 目前直接返回，重開用 revise 並保守重驗。需評估同目標缺陷局部重開，不偷換授權 |

安全與成本橫跨各面向。跨工具與易用性是交付面：pi 自動化與可攜技能能力分開說明，README 必須交代開始方式、接續及限制。

## 本批實作與驗證

- runner 開始時取累計執行剩餘時間、核心首次 worker 開始後期限的較小值，每次模型呼叫前再檢查。保留原限制、不改預算定義、不重設額度。
- 先重現過期 submitted 卷宗仍呼叫 reviewer，修正後零模型呼叫、原成果與狀態保留；另涵蓋檢查期間期限到達。
- 真實命令閉環：錯誤加總被拒收 → 同 session 修復 → 整合斷線 → 重載磁碟狀態 → 新 session 只做整合 → 正確成果完成。失敗檢查與兩次 run 保留，沒有重做已核對寫入。
- `npm test --prefix workflow-kit`：338 項，336 通過、2 項平台權限跳過、0 失敗。模型回覆是受控替身，檔案、狀態、檢查命令及接續是真實執行；不是本機模型效果證明。本批沒有本機模型呼叫。

## 接下來依序交付

1. **接續閉環**：區分唯讀失敗可重試、寫入中斷需確認、缺外部輸入需等待、預算耗盡需停。沿同卷宗保存成本；排除暫停時間若要採用，需調整契約與相容性，不能只刪核心檢查。
2. **成果核對**：讓已授權檢查的失敗具體回到修復交辦；語意核對要求與實際成果、支持／矛盾來源。不要硬編碼最近案例答案；必要的新介面再具體設計。
3. **完整旅程及入口**：先受控故障驗接線，再用有實際用途的本機任務驗新增工作、返修及接續後的最後成果。限定原總預算、保存失敗，不拼接局部成功；同步 README／V2／英文使用說明。

停止無假設抽樣、固定角色加碼及為單題擴張架構。前題雜湊異常保留待查，但不優先於完整工作閉環；此優先次序取代 holdout 報告的「先追雜湊」。尚未修好的語意誤驗，不因本批工程通過而撤銷。
