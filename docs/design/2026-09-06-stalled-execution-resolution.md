## 4. 第一批設計：讀取結果與診斷紀錄

### 4.1 讀取回條契約

保留 `case_read(path,startLine,maxLines)`，不新增重疊工具。回條由程式產生，檔名以 JSON 字串轉義，正文仍視為資料，不能藉偽造回條或指令文字取得權威。

| 項目 | 明確語意 |
|---|---|
| 行數與文字 | 沿用 `split(/\r?\n/)` 的行號與尾端空元素；空檔 `lines=1`，另以實際零 bytes 判定 `empty=true`。`a\n` 為兩元素。保留原有 CRLF→LF 正規化，不摘要或省略正文；不宣稱逐位元原樣回傳 |
| 範圍 | 顯示要求起點、實際回傳起迄與總行數；空檔、超尾皆用無正文範圍，不產生 `1–0` 假範圍 |
| 完整性 | `eof` 僅表示本次到檔尾；`wholeFile` 只在本次從開頭取得全部文字時成立，不能由尾頁、跨 session 或跨版本 coverage 推得。空檔從第 1 行讀取可 wholeFile；超尾請求不可 |
| 續頁 | 僅部分回傳時給實際 nextStartLine；完整檔、空檔、超尾不給假的下一頁。保留原有 `details.lines/startLine/truncated` 語意，新增狀態不偷改舊欄位 |
| 上限 | 沿用 24,000 UTF-16 code units 的正文容量單位，明示不是 tokens／bytes。新版整個文字回條含標頭不得超過 24,000；正文不靜默截斷。新標頭可能降低可回傳正文容量，這是須測的介面邊界變更 |
| 超限分流 | 多行合計過長可要求減少 maxLines；單行自身放不下則給有界 `LINE_TOO_LONG` 說明，不再建議永遠不會成功的行分頁。長路徑造成回條本身超限另給有界錯誤，不漏出任意路徑正文 |

超長單行這批只改善錯誤診斷，**尚不支援任意單行字元續頁**。執行者不得為此改凍結來源或開未授權 shell；需要準備其他材料時走既有 discovery／授權流程。一般資料任務仍可使用可處理的資料，不要求先編寫 executable checks。

來源 SHA256 必須由該次實際讀取的同一份 buffer 產生，再從該 buffer 解碼／切頁；不能在 tool end 重讀檔案後補配版本。coverage 身分至少含角色／session、實際解析來源、版本與範圍；不得一律將 Linux 路徑轉小寫。舊來源的完整覆蓋不讓新版自動通過，既有 fresh 驗證仍有效。這提供單次讀取快照的關聯，不承諾阻止其他程序在讀取中改檔或形成 OS 沙箱。

### 4.2 紀錄、隱私與失敗界線

新增獨立的 `traceVersion:1` metadata，不直接把 SDK event／Error／未知物件序列化。以 run/session/request/toolCallId 及單調遞增序號對齊，保存事件種類、階段、開始／結束／未完成、相對時間、可辨識錯誤碼、允許的路徑／範圍、上述來源版本及結果關聯；缺資料明示 unknown。舊 run 沒有 trace 時仍可讀，不能回填成完整觀測。

- 新 metadata 每事件最多 4 KiB、每 session 最多 128 事件且總共 256 KiB（均以 UTF-8 序列化 bytes 計）。這是待測工程限制，不是研究常數。到限額保留預留的 overflow／遺失計數與未配對摘要，標 `traceComplete=false`；不可靜默丟掉紀錄後宣稱軌跡完整。欄位字串亦受事件限額約束，身分被截斷時標未知，不拿截斷字串當完整 ID。
- 逐工具只保存必要參數：read 的正規化已允許來源／範圍；write 的已允許目的地／內容 byte 數及候選版本，不保存 body；check 的核准 ID／退出碼；discovery／result 的已接受 ID 或種類／驗證狀態，不複製 evidence／summary。任意被拒絕路徑、自由文字錯誤或未知 SDK 欄位不直接持久保存。其他路徑用安全的 scope 標籤；不得僅把字串冠名「相對路徑」就視為安全。
- **不改寫成整體去敏保證。** 既有 observations、check 輸出、final text、replyCorrections 仍可能含私密內容；此次只避免新增 metadata 再複製正文。公開 fixture 的深度紀錄限已確認可公開的材料，發布前檢查完整 artifact，不能只濾 write args 或宣稱掃描必能找出所有敏感內容。隱藏推理不保存。
- 新 metadata 不全部灌回模型。公開 fixture 的深度正文需有界去重保存，記錄保存耗時及截斷／遺失；兩組共用觀測器，計入總耗時。資料不全可限制歸因，即使產物正確也不得升格為完整約束驗證。
- 第一批維持 session 結束時交回紀錄，**不保證耐程序硬中斷**，不另建 checkpoint 服務。開始後沒有 end 標 incomplete；工具完成不等於紀錄已落盤。save 失敗時，呼叫端須仍拿到原始操作錯誤、另外的保存錯誤及可用記憶體證據；原錯誤不存在則以保存失敗為主。不再派工、不自動重播，不以再次失敗的 save 遮蔽首次原因。硬中斷後仍遵守 active attempt 防接管。

### 4.3 Context 隔離說清楚

新 session 保證不承接另一角色的對話 history，不代表沒有專案指引。現有 pi loader 仍會讀 agentDir 及工作目錄祖先的指引；本批**不關閉或忽略適用的使用者政策**。診斷記錄實際載入的作用域、指引版本／system prompt 版本，私有絕對路徑不直接複製到公開 artifact。實驗若意外載入其他專案內容，先修 fixture，不能帶著差異宣稱單變因。

已取用範圍與目前可見內容分開。紀錄 compaction 開始／結束及 request 關聯，SDK 不提供的壓縮範圍標 unknown；壓縮後不推定之前的精確正文仍可見。後續若做停滯判斷，壓縮、context 重建及角色切換都需重設相應觀測窗口。模型理解與否不能從 coverage 推算。

第一批不改階段預算、模型設定、材料 inline/indexed、角色數、指引載入規則或驗收標準。trace 保存失敗處置是相稱的可靠性修正；完整 crash 恢復不是 H1 交付前置。

## 5. 後續候選：有界調整，而非硬禁重讀

只有第一批對照仍暴露相應問題時才實作下列候選；它們不是預覽版現有能力。

- **規劃有交付責任。** 計畫只需確定目標、來源、交辦、相依與驗收，不先替執行者完整解題。本案現有 `Use the fewest useful packets` 和 `Do not do the work yet` 已存在，不能把相同句子再寫一次稱作修復。
- **時間保留。** 在既有整案總上限內分配規劃與後續執行／核對的額度，所有重試、修正和接續仍累計，不重置。先在此 600 秒 fixture 試驗規劃最多 120 秒、其餘共用 480 秒的單一候選，不作通用預設或文獻定律。時間到但尚無合法計畫時，保留未完成狀態，不拿殘缺文字直接派工；預算保留只能增加執行機會，不能保證足夠完成。
- **可觀察停滯。** 同版本、同範圍讀取結果不變，且沒有新增有關材料、有效候選產物、檢查改善或有效 discovery，才是候選停滯區段。先離線標記、不直接硬擋；新分頁、來源變更、修復後核對、獨立 reviewer 重新取證及等待已核准檢查均不得誤判。連續三輪無上述變化可作第一個待測提醒條件，但非通用真理。
- **一次有據的同 context 調整。** 提醒只含已取得的範圍、缺少的指定成果、實際錯誤及剩餘額度；模型應修復、做下一個有用動作或回報具體缺口，不強迫 write/result。模型說「我正在思考」或只改 placeholder 不算恢復；新產物 hash 也僅表示改變，不代表品質提升。
- **失敗後接手有條件。** 若仍無進展，先停止並確認原 session 與工具已結束，再以事實回條接回既有 discovery／規劃修正機制。進度異常是程式觀察，不冒充模型提出的外部缺料。最多消耗既有重規劃／attempt 限額，保留有效成果及未完成副作用資訊，不靠開新 session 重設預算。無安全接續證據時不得偷接管 active attempt。

後兩項需把不同停止原因（使用者取消、總時間、階段額度、停滯）分清；使用者取消後不自動恢復。相依受阻只影響相關工作，未解 discovery 仍會阻止整案假結案。這維持先前已同意的完整生命週期，不另造任務佇列。

審閱補上的 H2／H3 實作准入條件（不是第一批 runtime 變更）：

- 120 秒候選額度須明定涵蓋哪些規劃：初始規劃、discovery triage、amend 及整合後修正不可漏算。現行 `replan()` 的兩次限額與 `resolvePending()` 的規劃不是同一計數；控制器不能假設走任一入口就自然扣到相同配額，也不能把正常 discovery 全當停滯重試。
- 同程序計時用單調時計；未正常結束的歷史 run 不能只憑最後 save 的 elapsed 計價。對未結束的執行保守扣除尚未結算的已預留額度或停止自動接續，避免重啟增加可用額度；區分離線等待與執行時間。此規則未實作前，不宣稱耐 crash 的總預算保證。
- 自動接手須先禁止新工具、讓已開始的工具 settle、確認沒有仍擁有副作用的程序；`abort()` 回傳本身不是全部條件。等待有界；子程序／後代狀態無法確認、abort 失敗或 drain 超時，保留 active／unknown，不能解鎖重派。
- 非阻塞 discovery 的 triage 失敗不得由新控制器演變成全域停工。需測阻塞 A、獨立 B、已有驗收成果及待處置提案同時存在；B 在安全／總預算允許時仍可完成，整案仍不能假結案。
- 非程式任務沒有隱藏 oracle 可供 runtime 判斷品質。新文字、改變的 hash、讀取範圍、已持久回饋及真實檢查分別記為活動／證據訊號，不宣稱語意進展；不得把評分答案放進提示或用模型自稱有效解除安全限制。提醒只能建議調整，不硬性禁止合法重讀／尚未寫稿的研究。

## 6. 驗證順序與停止條件

### 6.1 工具契約與必要回歸

先測空字串、單換行、a、a加尾換行、CRLF、最後一行、超尾、只取尾頁；驗證 EOF 不等於全檔、行分頁不遺漏已承諾的正文。另測容量邊界／emoji／長檔名／超長單行、來源兩頁間變更、路徑等價與平台大小寫、實際 SDK 模型文字邊界。對固定有效讀取請求比較 A/B 去掉回條後的正文完全相同；臨界容量行為另列，不能把少讀內容冒充只改格式。

trace 測亂序／缺 end／取消／未知物件／超量／保存失敗；合成敏感字串分別放 read、error、check、discovery、final 等通道，核對新增 metadata 不複製，不誤稱 legacy log 也已去敏。測載入政策清單與角色 history 分離，compaction 不被當成已確知的記憶保留。修改 kit 跑完整套件；真實模型生成不能抵銷確定的回歸失敗。

### 6.2 有限生成批次

生成前建立唯一 manifest：鎖定模型／server build／實際設定、來源 hashes、工具與 prompt 版本、觀測器版本、採樣與 seed 是否實際送達／受支援、順序及不變權限。主案例仍為 `real-task-sources` 的四份凍結資料，答案只在外部評分器。新舊兩組**都是同版完整 CASE**，只由開發期測試注入切換讀取回條格式；不能重用歷史 native-pi 對 CASE 作為 H1 單變因基準，不提供新的使用者設定。

批次固定上限為 **1 次短 probe＋2 次 A/B＋至多 1 次條件式 holdout**：

1. 短 probe 使用同一模型與 scoped worker 工具，獨立目錄／新 session，只做「讀指定短材料 → 原值寫入指定檔 → 讀回核對」，最多 90 秒；不帶答案或摘要到後續組。單次語意失敗或超時標未能判定，照原計畫做 A/B，不能確診模型不相容。只有已確認服務／接線錯誤、越權或無法安全結束才停止整批。
2. A 為舊格式、B 為新格式，各最多 600 秒；固定 A→B 順序並揭露順序／暖快取混淆，不額外重啟服務。先確認主案例的最大可能來源回傳加回條仍在上限內。兩組共用同版安全修正、觀測器及 loaded-policy 集合；設定漂移、外來檔案或關鍵事件遺失會限制判讀，不事後挑版本替換。
3. 只有下表「舊敗新通且證據完整」觸發一次新版本 holdout，最多 600 秒。題目、來源與逐欄 oracle 必須在任何本批生成前凍結；選另一份同類公開資訊整理，不與主案例共用答案，也不為遷就結果換題。準備不完整則不開始整批。holdout 沒有舊版對照，只回答另一題是否完成，不證明跨題優勢。

最多 1,890 秒是各執行組的配置額度，執行期間的紀錄保存計入各組額度；不包含批次前準備、各組結束後的證據匯出及安全停止收尾，不宣稱整體工作必在 31.5 分鐘內結束。保存實際新增準備操作、檢查設定、人工介入與未知成本；舊結果、全部新失敗和未完成 usage 都保留。批次後停止，不自動遍歷 H2–H4；只依證據提出一項下一步，不要求使用者自己救援模型。未選定模型服務修改的具體範圍前不調整 BAT、模板或 MTP。

### 6.3 結果與採用分開裁定

`artifactPassed`（外部逐欄答案）、`workflowCompleted`（流程）、`constraints`（符合／違反／未知）與 `traceComplete` 分列。已知違反則整體失敗；關鍵約束或事件未知時，保留「成果正確但完整驗收證據不足」，不能當成改善。最終檔案乾淨不證明沒有曾寫後刪除；工具紀錄也不是 OS 監控。

| A 舊格式／B 新格式結果 | 預先確定的處置 |
|---|---|
| 工具契約／必要回歸失敗 | 不開始生成；先處理確定的產品缺陷 |
| 舊敗新通，且 B 完整約束與軌跡合格 | 記為本題改善訊號，做唯一已凍結 holdout，不宣稱穩定因果 |
| 兩組都通 | 可交付介面正確性修正；沒有品質提升證據，成本只描述本次，不另開 holdout |
| 舊通新敗 | 公開負面結果、不宣稱優勢、不重抽；單次差異不足認定因果回歸。若找到可重現內容遺失／安全退步，阻擋對應修正 |
| 兩組都敗 | 無任務效益證據；可保留通過回歸的介面修正，不自動疊加控制器 |
| 關鍵證據不足／安全停止 | 標未能完整判定，停止本批、不補抽；已知失敗仍保留，不能用 unknown 淡化違規 |
| holdout 通過／失敗 | 如實記另一題完成／未完成，兩者都結束本批，不換題 |

指標不混稱：傳送覆蓋只指版本／範圍；重讀是相同角色 session 下同版本與範圍再次傳送，不必然浪費；產物首次存在不等於結構有效或外部答案合格。準確驗收在外部執行，不把 oracle 放入 runtime 進度控制。更早失敗只可能是成本控制，不算核心修復。

本輪只完成審閱與設計修訂，尚未建立本批 manifest、凍結 holdout 或執行新的模型生成，沒有新增成功樣本。

## 7. 修改關聯與完整需求保留

| 需求 | 保留方式／預計受影響位置 |
|---|---|
| 大小憲法及隔離 | core/context 與 runner 新 session 不被撤掉；觀察摘要不攜帶另一角色推理 |
| 自查、修復到合格 | 保留 case_result 實際檔案／核准檢查拒收與同 session 修復；受總預算及授權限制，不保證零失敗 |
| 執行中新增工作 | 保留 case_discover 立即持久回饋、去重與補包；停滯紀錄不建立第二佇列 |
| 局部等待與接續 | 保留相依判斷、來源版本、active attempt 防接管；取消不當成自行重試授權 |
| 工具介面 | 第一批：pi/scoped-tools、sdk-session 及 pi-tools／pi-sdk 測試；必要時 runner 保存新增診斷欄位 |
| 可攜技能與公開說明 | 工作原則在技能／參照，保證由實際整合執行；實作後同步 V2、ARCHITECTURE、READINESS、GUIDE.en、STATUS，README 只更新真正改變的能力或證據 |
| 比較工具 | real-task-comparison 保存停止與可見呼叫證據；保留 executed 副本及歷史來源不修改；新測試檔同步 package 清單 |

第一批沒有新的使用者必填設定，也不要求改 init 範本。若後續採用跨平台共用的新欄位／預算設定，再按 MAINTENANCE 確認主要定義和版本相容性，不能只改 pi 後冒稱所有工具都有保證。

交付時用既有顯示入口回答四件事：保留了什麼、未完成什麼、是否具備安全接續條件、下一個可執行動作。沒有證據可接續就不能顯示「直接重試」。不要求新手閱讀完整 trace 或歷史研究，也不要求非程式任務先寫測試腳本；圖表、摘要等品質仍需適合該成果的核對方法。改動實際能力後才更新 README／英文的功能說明，不在首頁提前承諾候選功能；本輪已證實的 session／隱私限制則同步澄清。

## 8. 復盤與交付界線

已按[原始構想對照](../research/2026-09-05-layered-cooperation-direction.md)回看：分工是為了正確交辦與成果，不是切得越細越好；回饋是為了改變可執行方案，不只是記下失敗。現在的有用下一步是修復可重現的觀察缺口並測指定成果，不是擴大文件量、換一套框架或繼續加長指令。

研究與設計已保存，第一批產品修正及模型對照尚未執行。本輪不更動全域 pi、模型 BAT、服務、快取／MTP、備份或授權；不建立排程。既有預覽版與失敗結論不變。
