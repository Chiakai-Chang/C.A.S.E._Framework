# C.A.S.E. 完整解決方案設計

日期：2026-09-05。狀態：本輪提出的設計，尚未實作；不是效果驗收報告。

依據：[目標](../GOALS.md)、[原始構想復盤](2026-09-05-constitution-context-reconstruction.md)、[研究與替代方案](../research/2026-09-05-context-isolation-alternatives.md)。本設計是目前證據下的推薦方案，不宣稱存在對所有模型與任務皆最佳的架構。

## 1. 產品承諾與方案選擇

讓使用者照常交代工作，由框架協助 agent 保留目標、準備適量材料、執行、驗證與接續。優先服務本地模型，也能供強模型使用。使用者不必自行安排角色、填工作包或維護多份相同進度。

| 方案 | 優點 | 問題與裁定 |
|---|---|---|
| 只有指引與範本 | 易攜、低安裝成本 | 不能確保新 context 或可靠狀態轉移；保留為入口，不作全部產品 |
| 可攜工作契約＋共用核心＋薄整合層 | 共用語意、可測行為，沿用既有 AI 工具 | 需明示不同平台的自動化能力；採用此方案 |
| 自建通用 agent runtime | 能控制模型呼叫與執行流程 | 重複模型設定、工具、安全及 UI，偏離目標；不採用 |

完整指涵蓋需求至交付及失敗接續，不是每次必須執行所有階段。不是另一個聊天軟體、模型管理器或多人即時資料庫。不建立排程，不把訓練模型、向量資料庫或 RLM runtime 列為前置依賴。

## 2. 一個核心，三種可切換的工作方式

agent 根據工作結構選擇方式，只記錄簡短理由；使用者可以覆寫，無需先懂模式名稱。選擇是可修正的工程判斷，不是假裝已有準確分類模型。

| 方式 | 適用情況 | 做法 |
|---|---|---|
| 直接完成 | 短、低風險、資訊集中 | 同 context 執行及核對；沒有接續需要就不建卷宗 |
| 分階段接續 | 工作長、前後緊密相依 | 建卷宗、保存階段產物與精簡狀態，按需讀資料；在有用的階段邊界換 context |
| 工作包分工 | 有可分離且可驗收的產物，或規劃探索造成大量雜訊 | 規劃、執行與核對使用不同 context，最後做全域整合 |

工作包可以依序執行；不等於多模型或並行。預設同一本地模型、一次一個工作執行。只有工具支援且資料／寫入互不干擾時，才允許並行；同一工作目錄的修改預設序列化。不為了分工而將需要共同理解的緊密工作切碎。

從直接工作升級時，保存已有成果與未完成事項，不重新規劃已完成內容。分工不划算時，可將尚未執行的工作包合併並保留取代關係；不刪除失敗紀錄。

## 3. 責任邊界

| 部分 | 負責 | 明確不負責 |
|---|---|---|
| 可攜 skill | 判斷何時使用 CASE、如何整理需求與材料、何時回查或升級 | 不保證模型遵守，不偽裝執行隔離 |
| 共用核心 | 卷宗資料、版本、狀態轉移、相依檢查、context 組裝、驗證記錄與接續 | 不自行決定使用者授權、不呼叫任意模型、不另造通用工具迴圈 |
| AI 工具整合層 | 建立新 session、提供限定工具、取消／逾時、收集結果與用量 | 不複製核心狀態規則，不自行提高權限 |
| 執行者 | 依工作包產出成果、回報證據／問題 | 不設定自己的獨立核對為通過 |
| 核對者與整合者 | 依原始條件及實際產物核對，處理跨包衝突與全域驗收 | 不只相信執行者自述，不讓多數意見凌駕使用者限制 |

角色是責任，不是固定人數。相容工具可以用同一模型的不同 session 擔任。獨立 context 不表示錯誤在統計上獨立；可機械驗證的內容優先以實際測試核對。

## 4. 大憲法與小憲法的確切資料

大憲法不是另一份愈來愈長的全域 prompt，而是每個卷宗的全域工作約定；採用者既有的專案指引仍由其 AI 工具照常載入。

**卷宗契約：** `id`、`revision`、`goal`、`scope`、`constraints`、`acceptance`、`authority`、`budget`。限制與驗收各有穩定 ID；目標、來源及使用者授權分開記錄。全域條件不可只從工作包的局部測試推算通過。

**工作包：** `id`、`revision`、`contractRevision`、`purpose`、`constraintIds`、`inputs`、`dependsOn`、`writeScope`、`deliverables`、`checks`、`unknowns`、`budget`。每個輸入包含位置、版本／內容雜湊或取用時間、用途及是否必讀；輸出包含位置與可驗收條件。

所有適用且不可違反的限制直接放進執行 context，保留 ID 與原意；不能只給一個連結期待模型自行發現。規劃者為每個全域驗收條件標示由哪些工作包及哪項整合檢查涵蓋。核心檢查引用完整、ID 存在與覆蓋缺項；語意是否真的完整仍需核對者判斷。

小憲法不得修改大憲法。需求修訂產生新契約版本，未完成的工作包重新對齊；涉及的既有驗收失效重驗，無法判斷影響時保守標記待重驗。無關成果可保留，不能因一項修正全部重做。

## 5. Context 組裝與記憶

執行 context 組合為：適用指令＋全域目的及必要限制＋當前工作包＋必讀材料＋近期必要觀察。規劃過程的全部搜尋、爭論、失敗嘗試不自動繼承。必讀材料讀取失敗、來源版本改變或條件衝突時，停止該包並回報問題，不猜測缺漏。

其他材料以帶用途的索引按需取用；保留原文及產物，不做不可回復的摘要替代。大型資料先搜尋、篩選或程式切片，無須先做 RLM。核對 context 使用條件、產物與原始證據，不預載執行者的推理對話。

規劃者／整合者只持有全域契約、相依圖、目前結果、例外與下一步；完整產物在外部。短摘要必須附可回查來源，不能將所有 worker 對話匯回主 context。

context 預算由整合層回報模型上限、工具與指令開銷、輸出及推理預留後決定。不以字元數宣稱精確 token，也不把伺服器最大 context 當作目標。無可靠計數時標記估計；核心不得默默截掉必讀限制。過大時縮小工作包、外移非必要材料或回報容量不足。

長期知識只保留經核對、可重用的教訓，附來源與適用範圍；工作進度、失敗原始紀錄及長期知識分開。沿用 AI 工具既有 compaction，不另做一個不相容的壓縮系統。

## 6. 狀態、證據與失敗處理

工作包狀態：`planned → ready → running → submitted → verified`；任一未完成階段可進 `blocked` 或 `cancelled`。`ready` 要求契約有效、必需依賴已驗證、輸入可取得。執行回報只能進 submitted；只有符合核對策略的結果才能進 verified。

核對未通過：保存 findings，產生同包的新 attempt 回到 ready，連結原結果；材料或授權不足則 blocked。程序中斷的 running 記為 interrupted attempt，再判斷可重跑範圍；不直接當成功，也不盲目重播外部副作用。

卷宗狀態：`active / blocked / completed / cancelled`。completed 要求所有必需工作包有效、全域驗收逐項有證據、無未解決阻擋及整合通過。非必要工作須明列不影響已確認的驗收；不能為了結案自行把必需工作改為非必要。

每次 attempt 保存輸入版本、工具／模型設定、輸出位置與內容版本、檢查命令或方法、結果／退出碼、session ID、用量及失敗。證據標記來源為自述、實際工具執行或獨立核對，不能互相冒充。程序成功退出不等於任務完成。

預設每包最多兩次修正嘗試（初次執行另計），同一失敗且沒有新證據不原樣重試；這是可調整的操作預設，不是研究定律。開始工作前記錄總執行時間／模型回合上限，子工作不能各自再得到一份總預算。超限保存狀態並回報，不默默換模型或擴大預算。未知 token 成本記 unknown，不記零。

## 7. 安全、可靠性與可用程度

工作包中的資料不是額外指令；模型產生的檢查命令也不是可信程式。測試／命令只能經既有工具權限及批准機制執行。需要對外發送、刪除、部署或新權限時，回到既有授權邊界，不以工作包批准代替使用者同意。

核心可保證經自身 API 的結構與狀態規則；整合層可證明是否建立獨立 session、記錄真實工具結果。兩者都不宣稱共用可寫檔案系統上的強身分認證或防竄改。只靠限制可用工具而仍開放任意 shell，不算寫入範圍隔離。

同一卷宗只有一個狀態寫入者，worker 回傳結果而不直接改狀態。狀態更新採鎖、預期 revision 比對及同目錄暫存檔替換；同一請求 ID 重送不新增 attempt 或重做已知結果。殘留鎖需確認原程序已停止，不能憑鎖齡直接刪除。斷電或人工改檔不保證全自動恢復，doctor 明確報告差異。

## 8. 使用入口與平台策略

使用者安裝一次後直接交代需求；可用顯式 CASE 指令啟動或查狀態。初始化由 agent／整合層完成必要資料，不要求人填完整表單。沒有新授權或重大取捨時直接繼續，不每個階段都詢問。

第一個自動化接入選 **pi extension＋pi SDK**，不另寫模型／工具迴圈。核對過本機隔離套件 `@earendil-works/pi-coding-agent` 0.84.2 的 `docs/sdk.md`：提供 `createAgentSession`、`SessionManager`、資源載入及 session 事件。實作以固定測試版本為準，不假定未來版本相同。子 session 明確提供資源載入範圍，避免預設探索再次載入整套無關技能，並禁止 CASE 子工作遞迴啟動同一完整流程。

pi 使用原生套件安裝方式；可攜 skill 沿用目前已驗證的技能安裝入口。正式 README 只刊登打包安裝後實測過的指令，不先刊登假定存在的 npm 套件。首次設定只確認模型與必要權限；不清除全域 pi，不啟動未選定的模型服務。

Codex、Claude Code、Antigravity 共用工作契約與本地核心。整合層能力回報：是否可建立新 context、提供用量、取消工作、限制工具、驗證寫入隔離。不支援自動新 session 時，提供明確交接工作包，不在原對話切換角色卻標記成已隔離。平台相容狀態分「可讀寫卷宗」「可自動執行」「已做模型效果測試」，不合併成一個已支援勾選。

## 9. 儲存、相容與現有程式取捨

沿用 `.case-agent/`，不向採用者根目錄加入通用的 PLAN.md、MAP.md 或憲法檔，也不覆寫其 AGENTS.md。

```text
.case-agent/
  workflow.json                 歸屬、格式與設定
  tasks/                        原 v1 任務，遷移後保留唯讀歷史
  cases/<UUID>/state.json        該卷宗唯一權威狀態，含契約／工作包／attempt／證據索引
  cases/<UUID>/artifacts/        工作包快照、回報與必要原始證據
  cases/<UUID>/summary.md        可重建的人類閱讀視圖，不是第二份權威狀態
```

新格式使用 `case-workflow/2`。目前 v1 會拒絕陌生目錄，因此不得直接在 v1 資料中新增 cases 並期待舊工具可繼續寫入。升級必須顯式執行：檢查無寫者→在資料目錄外建立可還原備份→產生／驗證新資料→切換格式。中斷不提交新 manifest；重跑可辨識暫存狀態。舊工具拒絕 v2 是預期保護，不是假裝雙向相容。

v1 已完成任務保留歷史完成狀態，但不得轉成新格式的獨立驗收通過；匯入引用為 legacy record。恢復工作時另建有來源關聯的新卷宗。未知所有者、外來檔案、符號連結／路徑逃逸與無法備份時停止遷移。更新／移除技能不刪卷宗。

重用現有 installer、CLI 入口及有用測試；將 `case.mjs` 拆出小型共用模組，不把新流程全部堆進單檔。根目錄 M0 保留研究用途，不提升成新核心的依賴。

## 10. 實作單元與順序

以下為設計交付的工作順序；各單元同時包含測試、文件與範本更新，不把文件留到最後補。

| 順序 | 工作單元與預定位置 | 可獨立核對的交付 |
|---|---|---|
| 1 | `workflow-kit/skills/case-workflow/scripts/core/{store,contracts,state}.mjs`；CLI 路由與 migration 測試 | 版本化卷宗、工作包、相依及狀態規則；既有資料安全升級／拒絕 |
| 2 | `scripts/core/{context,evidence}.mjs`；context／review 測試 | 必要約束不截斷、有版本的工作包、來源過期偵測、核對及整合條件 |
| 3 | `workflow-kit/integrations/pi/`；runner／中斷測試 | 真正新 session、單一本地模型依序規劃／執行／核對、用量、取消、預算與接續 |
| 4 | 現有 SKILL、references、assets、README、HOSTS、GUIDE.en、READINESS | 清楚的直接／階段／分工入口；隔離專案安裝與全流程實例；其他平台不誇大能力 |
| 5 | `workflow-kit/evaluation/` 與 `docs/evaluation/` | 真實本地模型的配對結果、原始證據、失敗分類；根據結果修正而非只宣布測試通過 |

單元 1／2 不另寫通用工作流語言；由窄操作建立／修訂契約、準備工作包、開始 attempt、提交成果、記錄核對及整合完成。CLI 與 pi 都呼叫同一套狀態函式，不各自維護 JSON。詳細命令與函式簽名在實作計畫中定稿，使用者目前不需學習尚未存在的命令。

## 11. 驗收與效益判斷

**行為驗收：** 未齊資料不能執行；執行者自述不能成為獨立核對；來源變動使相關核對失效；相依環拒絕；重送不重複；中斷可安全接續；預算停止；局部通過但全域失敗不能結案；安裝、升級、移除不毀損使用者資料。加一條不依賴模型的完整流程測試確認整體可接通。

**模型驗收：** 固定目前本地模型、量化、聊天範本、pi 版本、工具與初始資料。至少覆蓋程式修正、跨檔案整合、文件／資料整理、缺資料回報及中斷接續；同一任務比較清楚指引的單 context、工作包分離、再加獨立核對。每組先做三次配對執行作為問題探測，全部公布；小樣本不作普遍顯著性宣稱，結果不穩定則針對原因追加而非挑最好一次。

共用最終驗收與端到端預算；記錄初始及重試成果、約束遺漏、人的介入、總時間與全階段 token。保留未參與調整的任務作回歸。雲端規劃是另列條件，不混入本地同模型比較。

若較簡單方案同樣完成且成本較低，就採較簡單方案；若品質增加但耗時更多，呈現取捨而非宣稱省 token。若只有工具格式出錯，修整合／範例，不追加角色；若工作包漏資料，修材料組裝；若全域整合失敗，修相依／驗收；若模型能力不足，明示限制，不靠無限重試掩蓋。

完整交付包含可用流程、例子、安裝維護及可查證的本地結果；不以等待使用者自行實測結束。不能事先承諾效果必勝，但必須交付誠實的比較及依結果調整過的方案。

## 12. 維護與知識保存

本設計定義下一版行為；現行 ARCHITECTURE／READINESS 仍描述已實作版本，實作時逐項同步。MAP 指向本設計；原始構想、研究、失敗及舊驗收保留，不因新方案改寫歷史。

研究支持與工程選擇分開：context 外移與接續有來源支持；預設序列化、重試上限、檔案配置等是本專案可修正的設計選擇。後續只記錄會改變方法或有重用價值的發現，不累積例行儀式。首先完成能讓本地模型走完工作的系統，再用證據決定增加什麼，而非為論文或框架規模增加功能。
