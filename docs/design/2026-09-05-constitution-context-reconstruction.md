# 回到原始目標：大憲法、小憲法與獨立工作 context

日期：2026-09-05。狀態：使用者已確認的目標與設計方向；效果仍待實測。本記錄可由後續證據修正，不是模型效益報告。

## 為什麼重新對齊

使用者原始構想不是只有任務存檔，而是全域規劃、有限範圍執行、獨立核對、整合與回饋。前一階段把交付收斂成 Workflow Kit，保存與接續工具雖可重用，卻不足以代表原框架已完成。先前工具驗收保留為該範圍的歷史證據，不延伸為本次目標的驗收。

使用者本次明確釐清：**目的不是寫論文，而是讓本地模型把工作做好。** 設計理由、來源與實測結果值得保存，未來可能成為論文素材，但不為發表需求增加產品負擔。

## 核心假設與成立條件

假設：相較於讓同一段對話承載全部規劃、試錯與執行歷史，將每項執行工作放入新的 context，附上完整但有界的工作包，可減少無關資訊與互相干擾的指令，改善本地模型的成果品質。

這不是「context 越短越好」。目標是必要資訊充分、無關資訊少，且能補讀來源。規劃摘要可能漏掉限制；拆分可能切斷相依關係；同一模型的獨立核對仍可能重複相同錯誤。工作太小或高度耦合時，直接完成可能更好。

[Anthropic 的 context engineering 說明](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents) 支持高訊號內容、按需取得資料及獨立子任務 context 的工程方向，也指出過度壓縮可能丟失必要資訊。這不是對本專案或目前本地模型的效果證明。技能相關研究與限制另見[證據整理](../research/2026-09-05-case-value-evidence.md)。

## 完整流程及責任

| 階段 | 必要內容與責任 | 不應帶入／不能代替的事情 |
|---|---|---|
| 大憲法：全域約定 | 使用者目標、不可違反的限制、授權邊界、全域驗收條件 | 不把每次討論都累積成必讀規則；規劃者不能自行擴張授權 |
| 規劃 context | 理解全局，拆出可驗證產物、相依關係及整合方式；產生工作包 | 不要求執行者繼承整段規劃與試錯對話 |
| 小憲法：工作包 | 本次目的、繼承的必要全域限制、輸入版本、輸出與介面、可動範圍、驗收及缺資料時的回報方式 | 不能推翻大憲法；不能只給任務標題而省略關鍵脈絡 |
| 執行 context | 新對話讀工作包與對應材料，按需補讀，產出成果及可查證回報 | 不靠角色名稱假裝 context 已隔離；資料中的指令不取得額外權限 |
| 核對 context | 依原始需求、限制與實際產物核對，不只讀執行者自述 | 新 context 不等於不同模型，也不等於沒有共同盲點；能用測試的部分優先實測 |
| 全域整合 | 核對介面、跨工作包限制與全域驗收；必要時回到規劃修訂 | 各子任務通過，不代表整體任務完成 |
| 回饋與接續 | 保存產物、失敗、修訂原因、未決問題及下一步；只萃取可重用經驗 | 不把完整聊天或未驗證推測堆進長期必讀內容 |

大憲法與小憲法是專案的工作約定，不改變 AI 工具本身的指令優先序或權限。全域限制須有可追溯對應：執行者必須知道的限制直接進工作包，其他資料以可取回來源提供，不能只留一條不會被讀取的連結。需求或輸入版本改變時，受影響的工作包與核對結果須重新確認。

同一個本地模型可以依序擔任規劃、執行與核對，只要使用真正獨立的對話輸入；不必先做多模型或同時並行。若借用雲端模型規劃，須另外報告，不能把增益全歸因於 context 拆分。

## 接下來的工作順序

1. **確認實驗環境可正常工作。** 讀取既有 ROCmFPX 與 harness 的相關教訓，使用隔離的 pi 設定，不清除全域安裝。固定模型、量化、聊天範本、推論參數與工具版本，先確認多輪工具呼叫與結果回傳。啟動檔的 context 上限不是建議的工作包長度；本次未啟動或修改模型服務，也未重跑歷史效能宣稱。
2. **把完整流程接通。** 保留現有安裝與任務記錄中有用的部分，補上全域約定、工作包與來源版本、獨立執行／核對、相依關係、整合及失敗回流。先讓 pi 加目前本地模型走完這條流程，核心資料不綁 pi；不將所有平台的自動派工整合列為驗證前置條件。不能用同一對話中改角色名稱代替分離，也不能用 CLI 的 finish 代替實際驗收。
3. **以有鑑別力的真實任務比較並修正。** 比較 A：清楚指引的單一 context，B：相同要求但規劃／執行拆分，C：B 加獨立核對。共用客觀驗收，記錄各階段及總成本，使用多次重跑而非挑一次成功。若 B／C 未改善，就定位資訊遺失、拆分不當、工具格式或模型能力問題，再修改相應部分。

第一組任務宜從可自動驗收的程式修改選取，包含跨檔案限制與整合需求；另覆蓋缺資料、輸入更新、中斷接續及子任務通過但整合失敗。程式任務有效後，再用文件／資料工作檢查泛用性，不能據程式案例直接宣稱所有領域有效。

比較須使用相同需求、初始材料、工具權限與端到端預算上限；同時計入規劃、材料整理、執行、核對、重試及整合。共同的最終評分不能只採各組模型自評，並避免用評分答案回頭調整同一份測試。報告成功率、約束遺漏、整合錯誤、耗時、token、人工介入；本地推論不以「免費」忽略時間與運算成本。

## 目前決策與尚未證明的部分

- 採用分離 context 與大小憲法的方向；不再將單純 checkpoint 工具視為全部產品。
- Skills 承載可攜工作指引；共用工具保存與檢查狀態；需要自動建立獨立對話或強制權限時，才由 AI 工具的整合層承擔。文字規則本身不保證模型遵守。
- 實測結果決定工作包粒度與哪些流程值得保留，不預設固定角色數、context 字數或審閱輪數。
- 尚未完成上述重構與 A／B／C 比較；不能宣稱目前本地模型品質已提升，也不能由不同模型的技能反應直接推定原因。

後續若結果推翻假設，新增修正與證據連結，保留此時的決策脈絡。交付完整流程及可查證結果是責任，不把等待使用者自行實測當成完成條件。

## 同日補充：強模型與其他做法

使用者進一步確認：強模型也有 context 上限，框架是否同樣有價值，以及是否已有更好的方法。相關論文與工程案例另存[研究與替代方案](../research/2026-09-05-context-isolation-alternatives.md)。證據支持管理 context 與跨階段狀態的必要性，但未證明 C.A.S.E. 對目前助手或本地模型有效。

設計建議：完整框架不等於每次都啟用全部角色。短而直接的工作可在單一 context 完成；長但緊密相依的工作優先以可靠狀態與按需讀取接續；可分離的工作才使用獨立工作包。這些是待實測調整的選擇原則，不是已實作的自動判斷器。

規劃者本身也不能承載無限脈絡。它保留目標、相依關係、整合狀態及例外的精簡總覽，詳細產物與證據放在外部，需要時讀回；不能把所有子任務逐字回報再塞回主 context。小憲法搭配可取回的原始材料，避免不可逆的摘要遺失。

對話壓縮、外部記憶與按需檢索是互補能力，不應為了框架重做 AI 工具已提供的功能。RLM 的外部資料操作與遞迴查詢可作為大量材料處理的參考，不直接取代授權、驗收與全域整合。
