# 執行停滯方案：多面向審閱、分歧與裁定

日期：2026-09-06。使用者要求充分考量專業與利害關係人、多輪討論及收斂。本次審閱對象為[停滯診斷與修正設計](2026-09-06-stalled-execution-resolution.md)，不是重新設計整個 CASE，也不是再次宣稱產品完成。

## 方法與界線

實際用了三條獨立 agent 審閱線與主責整合：M 模型／工具／context；S 控制／安全／可靠性；E 驗證／採用／品質。第一輪彼此不交換結論；第二輪主責轉交具體反方意見，要求對衝突提出接受條件，而非重複投票。主責另核對實作、原案、使用者已指定來源及跨領域需求。

這些是 AI 模擬的專業和利害關係人觀點，**不是外部真人專家評審或使用者訪談**；共用模型可能有共同盲點。MECE 用於檢查是否遺漏責任與情境，不代表證明所有未來問題都已窮盡。相交議題有主要負責線，必要時交叉挑戰，不按角色數量製造儀式。

## 第一輪：獨立問題清單及處置

M／S／E 各提出六項重要設計缺口，共 18 項。下表的「採納」表示已修訂設計，**不表示程式已實作**。

| ID | 原設計缺口與可能後果 | 裁定／可驗收的修正 |
|---|---|---|
| M1 | EOF 易被誤稱全檔；空檔、尾端空行、CRLF 未定義 | 採納 §4.1；eof／wholeFile／範圍分開，保留行號慣例與換行正規化，空檔有明示狀態 |
| M2 | 單行超限仍要求減少行數，可能永遠失敗 | 採納 §4.1；區分多行合計超限與 LINE_TOO_LONG，這批不擴大字元分頁 API |
| M3 | 事後算 hash 可能對不上實際回傳 bytes，跨版本 coverage 失真 | 採納 §4.1；由同一次讀取 buffer 算來源版本，保留來源變更拒收與平台路徑差異 |
| M4 | 曾取用不等於 compaction 後仍可見 | 採納 §4.3；分開歷史覆蓋與當前可見性，記錄可取得的壓縮事件，未知不補造 |
| M5 | 新 session 仍可能載入 agentDir／祖先指引 | 採納 §4.3；隔離限於角色 history，保存載入集合，不任意關閉使用者政策 |
| M6 | 深度 trace 本身增加磁碟量與時間，干擾有限預算 | 採納 §4.2、§6.2；同版觀測器、有界去重及成本記錄，正文不反覆注入 prompt |
| S1 | 「不保存密鑰」與既有全文 observations 存在矛盾 | 採納 §4.2；新增 metadata 避免複製正文，但明示 legacy log 仍可能敏感，公開檢查整份 artifact |
| S2 | trace 無格式版本、上限與 plain JSON 邊界 | 採納 §4.2；明示 schema、allowlist、事件與總容量、overflow／unknown，舊 run 可讀 |
| S3 | 紀錄落盤失敗可能遮蔽工具錯誤，硬中斷資料不明 | 採納 §4.2；原錯誤＋保存錯誤＋記憶體證據分開，停止派工；不承諾 session 內 crash 耐久 |
| S4 | elapsed 最後保存值漏計 crash 前時間，Date.now 可回撥 | 採納為 §5 候選控制准入；單調時計、未結額度保守處理，不能稱現有欄位已保障全部重啟 |
| S5 | abort 回傳不等於所有工具／子程序副作用已結束 | 採納為 §5 准入；禁止新工具、已開始者 settle、確認副作用擁有者結束，否則不接管 |
| S6 | discovery triage 與 replan 不共用同一限額，可能阻擋獨立工作 | 採納為 §5 准入；明確階段計價與重試歸屬，測 A 受阻／B 獨立；現有總額上限仍有效，不誇稱完全無界 |
| E1 | 「舊／新」可能誤用原生 pi 對 CASE 的混合基準 | 採納 §6.2；兩組皆同版 CASE，只差回條；短 probe 使用相同 scoped worker，模型參數／順序可追查 |
| E2 | 未涵蓋兩組皆通、新敗舊通、證據不足等結果 | 採納 §6.3 完整處置表；契約修正採用與任務效益分開，批次有整體上限 |
| E3 | 新標頭吃掉容量，未必只改格式；指標定義模糊 | 採納 §6.1–6.3；主案例檢查正文等量、臨界政策另測，覆蓋／活動／成果／品質分列 |
| E4 | 最終檔案正確不代表完整約束皆可驗證 | 採納 §6.3；artifact／workflow／constraints／trace 分列，關鍵 unknown 不算完整通過 |
| E5 | 非程式工作不能靠 hash 或模型自稱判有效進展 | 採納為 §5 准入；runtime 不接觸 oracle，保留研究／核對的合法重讀，不以活動假裝品質 |
| E6 | 改善後才挑 holdout 易選題偏差，採用負擔未納入 | 採納 §6.2、§7；生成前凍結唯一題目／來源／oracle，失敗不換題；新增操作與未知準備成本都保留 |

主責另確認：現有 read 工具主要保護專案邊界與設定目錄，不能單靠工具存在便聲稱所有文字約束都強制生效。因此 §6.3 仍須核對任務限定的來源／行為；工具軌跡不是作業系統隔離證據。

## 第二輪：最強反方與延伸討論

### A. 為何不直接先查模型？回條可能根本無效

M 與 E 指出：原生 pi 未讀來源就偏離，CASE worker 沒有重讀迴圈；H1 不能解釋全部失敗。原先先跑兩次十分鐘再做短工具往返，可能浪費成本。

裁定：確定的介面缺口仍修；生成前增加至多一次 90 秒短往返，再做既定 A/B。M／E 第二輪反對把單次短測失敗當模型不相容，主責採納：只有確認的服務／接線／安全故障才停止整批；語意失敗與超時保留為未知，不自行換模型或重抽。

### B. 追求完整安全是否又讓小修變成大型 runtime？

S 指出 trace 需要隱私、容量、序列化與失敗處置；但完整 crash 預算、子程序 drain 與 discovery 重新排程不是 H1 的前置。

裁定：第一批只完成回條、有界新增 metadata 及保存錯誤保底。既有全文紀錄保留相容，不冒稱已去敏；S4–S6 成為未來啟用 H2／H3 的准入條件。保留風險不是略過：它們有指定位置與反例，控制器未通過前不得啟用。

### C. 為了隔離，可否把全部上層指引關掉？

M 查到 loader 會讀 ancestor 與 agentDir 指引；主責核對 SDK 原始碼後確認。直接關掉可能讓合法的專案／使用者政策失效，也混入另一個 A/B 變因。

裁定：不關閉。精確承諾為角色 history 分離，記錄適用指引集合與版本。實驗夾入其他專案內容要修 fixture，不讓一般用戶每次批准載入指引；必要權限不由測試便利性決定。

### D. 為了處理所有文件，要不要立刻新增字元分頁？

M 認為目前長單行錯誤訊息有問題，但另開 API 會擴大範圍。主責提出區分可減少行數與單行不可容納，M 在第二輪要求禁止暗示可改凍結來源或使用未授權預處理。

裁定：接受有界、可行動的錯誤，不增加新工具；長單行完整讀取能力仍未提供。此缺口不能從文件中抹掉，也不能以格式錯誤修復宣稱已支援所有資料。

### E. 新版一次失敗，是否必須撤回修正？

E 反對把單次模型差異當因果回歸，也反對只報正面結果。介面契約、任務效益與公開發布是不同決策。

裁定：可重現的內容遺失、安全或合法分頁退步會阻擋採用；僅一次新敗舊通則公開負面結果、不宣稱優勢、不補抽。兩組皆敗仍可交付已驗證的介面正確性修正，但核心品質效果仍未證明。holdout 單次成功不證明泛化優勢。

## 收斂與剩餘工作

18 項審閱意見皆已有設計處置；M／S／E 第二輪提供的接受條件已納入。沒有重大分歧需交由使用者裁決；有共同不確定性：回條修正是否改善本機模型交付，尚待實測，不能用角色共識消除。

裁定落地核對另修正一處計時口徑矛盾：執行期間的紀錄保存必須計入各組額度，只有事前準備、組後匯出與安全收尾另列。文件澄清後現有 kit 220/220 通過；這是既有回歸未退步，不是候選方案的模型驗收。

這輪完成的是**設計優化與驗收規則**。產品程式未修改、新生成未執行、holdout／批次 manifest 尚待實作階段準備。下一步可直接按 §4 和 §6 完成第一批修正與有限驗證，毋須再開一輪泛泛研究或要求使用者自行測試。

文件保存結論與分歧，不複製整段聊天；主設計是目前方案的單一來源，本頁保存採納理由，MAP 導航兩者。README／套件說明／英文／架構同步澄清已證實的 session 與紀錄隱私限制，不提前宣稱候選功能；不建立排程、不動模型服務或備份。
